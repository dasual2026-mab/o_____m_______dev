# 개발 환경 잇기

대표가 계정을 만들고, 그 뒤 Claude Code 세션이 잇는 차례다.
계정은 대표가 회사 메일로 직접 만든다. 비밀번호와 키는 대화창에 붙여 넣지 않는다.

## 1. 대표가 하는 일

### 1.1 GitHub
1. github.com에서 회사 메일로 계정을 만든다.
2. 2단계 인증을 켠다.
3. 새 저장소를 만든다. 공개 범위는 Private이다. README와 .gitignore는 넣지 않는다.
4. 저장소 주소를 세션에 알려 준다. 주소는 비밀 값이 아니다.

무료 요금제로 충분하다.

### 1.2 Supabase
1. supabase.com에서 회사 메일로 계정을 만든다. 2단계 인증을 켠다.
2. 새 프로젝트를 만든다.
   - 이름: `om-dev`
   - 리전: Northeast Asia (Seoul)
   - 데이터베이스 비밀번호: 화면이 만들어 주는 값을 쓰고 비밀번호 관리 도구에 보관한다.
3. 프로젝트 번호(Reference ID)를 세션에 알려 준다. 비밀 값이 아니다.

개발용 프로젝트는 무료 요금제로 시작한다.
무료 프로젝트는 일주일 동안 쓰지 않으면 멈춘다. 다시 켜면 이어 쓸 수 있다.
유료 요금제는 운영용 프로젝트를 만들 때 금액을 알리고 승인받는다.
운영용 프로젝트는 지금 만들지 않는다.

## 2. 잇는 차례
`server` 폴더에서 한다. Supabase 도구는 `npx supabase@3.4.0`으로 부른다. 따로 깔지 않는다.

1. 대표가 `npx supabase@3.4.0 login`으로 로그인한다.
2. `link --project-ref 프로젝트번호`로 잇는다.
3. `db push --remote`로 변경 파일을 적용한다.
4. 대표가 `scripts/setup-dev-secrets.ps1`을 돌린다. 키 아홉 가지와 svc_app 비밀번호를 만들어 비밀 값 저장소에 넣는다. 값은 화면에 나오지 않는다.
5. `functions deploy api --use-api`로 앱 서버 함수를 올린다.
6. 대표가 대시보드에서 Data API를 끈다.
7. 저장소를 GitHub에 올린다.

svc_admin과 svc_jobs의 로그인은 관리자 서버와 예약 작업을 만들 때 건다.

## 3. 개발용 프로젝트에서 확인할 것
설계 문서가 '확인 필요'로 남긴 것이다. 로컬 검사로는 볼 수 없다.

| 확인할 것 | 근거 | 결과 2026-11-26 |
|---|---|---|
| Data API를 끈 채 서버 API가 접속 역할로 직접 접속하는지 | 기술설계_3 2.1 | 접속은 됨. Data API 끄기는 대표가 대시보드에서 한다 |
| 접속 역할에 행 단위 보안을 건너뛰는 속성을 줄 수 있는지 | 기술설계_3 2.1 | 됨 |
| 관문의 기본 인증 검사를 끈 함수가 요청을 받는지 | 기술설계_4 2.3 | 됨 |
| 공통 풀러로 접속 역할이 접속하는지. 사용자 이름은 `역할.프로젝트번호` 꼴이다 | Supabase 공식 문서 | 됨. 트랜잭션 방식 6543 |
| 실시간 신호의 연결 | 기술설계_4 10.2 | 그 기능을 만들 때 본다 |

다시 확인하는 명령. `server` 폴더에서 돌린다.
- 표 수와 잠금: `npx supabase@3.4.0 db query --remote --read-only --file scripts/verify-remote.sql`
- 보안 점검: `npx supabase@3.4.0 db advisors --remote --type security`
- svc_app 접속: `node scripts/check-dev-db.mjs`. 대표 사용자 폴더의 사본이 있을 때만 돈다

## 4. 키
키 아홉 가지의 이름은 `server/.env.example`에 있다.
- 무작위 32바이트를 만들어 대시보드에 바로 넣는다. 만드는 명령은 세션이 안내한다.
- 대표가 모든 키의 사본을 서버 밖 안전한 곳에 보관한다.
- 변환 키를 잃으면 같은 사람인지 대조할 수 없다. 변환 키는 바꾸지 않는다.
- 개발용 프로젝트의 키는 개발용으로만 쓴다. 운영용 키는 따로 만든다.
